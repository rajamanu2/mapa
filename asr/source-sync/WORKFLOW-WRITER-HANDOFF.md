# Source workflow and dual-dispatch handoff

Local implementation only. Do not enable `original_writers_coordinated` or deploy this module on the strength of its unit/integration tests alone. The archive is a reference snapshot; compare it to the actual deployed PHP before applying any patch.

## Implemented private command boundary

`SourceWorkflowCommands.php` / `source-workflow-command.php` implement `mapa-asr-workflow-command-v1`. The source remains authoritative for administrative sessions, completed manual trip entries and repairs. This does not implement an original manual "Start Trip" action: the archived form records pickup and drop together after the trip.

The envelope is `contract, company_id, request_id, actor_id, action, record_id, expected_revision, values`. `record_id` is the **source ambulance ID** for all actions. UUID request IDs persist across retries. Fetch `context()` on the authenticated server, show it to the authorized actor, and send its opaque revision unchanged. `context()` contains dates/driver IDs and must not be public or included in general snapshots.

Actions:

- `session.start`: record_date, status, odo_reading (decimal string; null for Off Road).
- `session.close`: daily_status_id, closing_odo (must equal calculated source closing).
- `trip.record`: daily_status_id, driver_id, trip_type, pickup_date/time, drop_date/time, distance_kms, from/to PHC/secretariat/village IDs and patients array. Strict keys and explicit nulls. Types patient_village, referral, deadbody, other. Every patient row has name, age, gender, phone, purpose. Unused demographics for other are null/empty; no diagnosis is inferred. Mileage applies to the first patient only and updates closing odometer once, in the same transaction as the idempotency receipt.
- `repair.complete`: repair_id, end_date, return_to_road=true, odo_reading. This changes the source road record only, never MAPA duty, driver assignment, GPS validity or active journey readiness.

Private ACL per actor: actions, source_user_id, ambulance_ids, driver_ids, phc_ids, trip_phc_ids, vehicle_types. This service-account bridge does not inherit PHP web-session privileges; commissioned grants must mirror and revoke with the original role/category/PHC authorizations. Do not accept grants or source_user_id from request JSON. Trip destination grants may differ from operating PHC grants. Use exact IDs rather than matching phones/names.

Use a separate strong `secret` for signed requests/responses and `ledger_secret` for request HMACs. No raw patient payload or unsalted payload hash goes into the command receipt ledger. Private config stays outside document root. The workflow writer needs SELECT on required fields/tables, INSERT on amb_daily_status/amb_trips/ledger, narrowly scoped UPDATE on daily status, repair status/end_date and ledger. The tested MySQL 8 image additionally requires LOCK TABLES on this source database for FOR UPDATE reads of read-only master tables; granting that avoids unnecessary UPDATE rights on ambulance/driver masters. Confirm this on the deployed MySQL version. It does not need account writes, DELETE, DDL or access to authentication secrets (users lookup needs user_id only). Run SQL migrations separately under reviewed deployment credentials.

## Shared source ownership implementation

`SourceDispatchCoordinator.php` supplies a database-scoped MySQL advisory mutex and durable `mapa_dispatch_reservations` ownership (SQL in dispatch-reservations.sql). All participants must share the same database and mutex. Durable unique active ambulance and driver indexes stop duplicate MAPA ownership even if a second caller bypasses process locking. Ownership never automatically expires: a timeout or a dropped phone cannot make an active ambulance dispatchable.

Internal `reserve(db, company, journey, vehicle, driver)` requires prior authenticated actor/tenant/resource authorization; it is not an HTTP authorization layer. It checks unfinished original CAD/source trips, today's open On Road session, current driver/vehicle PHC+category and repairs. Retry with the same journey returns its existing ownership; a terminal returned reservation **must never be treated as a new dispatch grant**. `transition(db, company, journey, expectedVersion, next)` performs ordered state changes. Completion/cancellation releases active uniqueness while retaining evidence. Caller must enforce journey ownership, permissions, and clinical/operational workflow separately. Reservation completion does not itself record source mileage.

MAPA needs a durable outbox/saga: reserve source before committing local assignment, retain one journey/request identity, handle unknown outcomes by authoritative lookup/retry, commit MAPA assignment, then advance source ownership with expected version. Do not automatically cancel ownership after a network error. Compensate only when MAPA can prove local assignment did not commit. The separate signed dispatch protocol is being implemented alongside this package; this original-writer patch does not itself wire MAPA assignment/outbox behavior. Validate the final saga separately.

## Original source patch package

Run `stage-original-writer-patch.py --archive <ambulance.zip> --output <fresh-directory>` to generate local review artifacts only. It emits original/patched copies, SHA-256 before/after manifest and a SQL mutation inventory. It does not apply or execute the source. **Latest complete local review package: `planning/original-writer-patch-v8`; v1-v7 are superseded review snapshots.** The v8 package covers all 15 PHP files containing source mutations in this exact archive. It keeps operational forms and original permission checks, acquires the shared lock before source checks/writes, blocks MAPA-owned resources, validates dispatch session/driver compatibility, prevents completed CAD mileage replay, prevents terminal cancellation, and stops the generic status endpoint from marking complete without the existing completion form. Automatic session closing in running and analytics excludes active MAPA or unfinished source trips. CAD deletion allows undispatched pending/cancelled records only; existing dispatch history is retained.

The added coverage is `cad_save_incident.php`, `cad_dispatch.php` (call-attempt timeline POST), `cad_incident_list.php`, `ambulance_analytics.php`, `setup_running_db.php`, `cad_db_init.php` and `self_heal_ambulance.php`. The last three are maintenance gates: included web bootstrap becomes a verified no-op while coordinated, direct setup is denied, and actual reconciliation requires explicitly disabled coordination plus standalone CLI maintenance and no active MAPA/source journeys. Inline ALTER/seed fallbacks in drivers/repairs fail closed instead of silently changing the schema. **This does not execute the archived destructive CAD collation repair or account/role seeding.** Those require separate reviewed offline maintenance if ever needed.

`MAPA_SOURCE_COORDINATION_CONFIG` must point to a private file outside the document root. It requires boolean `enabled`, boolean `maintenance_mode`, and a reviewed `schema_sha256` metadata receipt for the original website connection. Both booleans cannot be true. Command/workflow endpoints also require `command_schema_sha256` / `workflow_schema_sha256` / `dispatch_schema_sha256` for their actual SQL accounts; column-level SQL grants deliberately expose different metadata. Compute receipts with `SourceCoordinationPolicy::schemaReceipt` during reviewed schema/permission commissioning, never auto-accept a new receipt on failure. All command endpoints acquire the shared mutex, load this policy, verify their account receipt and refuse disabled/maintenance/missing/drifted attestations before execution. This is schema/account attestation; deployed code hashes are still checked separately.

SourceCommands now participates in the mutex and refuses ambulance/driver master edits against MAPA reservations or original open trips. Its source/mobile copies match, and `SourceDispatchCoordinator.php` is mirrored into mobile as their required helper. Master writer grants need SELECT of reservation ownership and only amb_trips id/daily_status_id/driver_id/drop_date/drop_time plus daily-status id/ambulance_id. They still cannot SELECT patient columns. The policy inventory now includes mapa_manual_commands; master service users need metadata-visible SELECT(request_id) only, without patient data. Metadata receipt coverage needs limited metadata-visible privileges on the other policy tables. Do not broaden patient/account data access to satisfy a receipt.

The original CAD checks were outside their SQL transaction. Holding the mutex across the **entire original request** makes the check+commit sequence mutually exclusive with participating MAPA writers. Shutdown rolls back any abandoned transaction and releases the lock. Holding it while rendering original pages may increase contention; replace with narrowly scoped service calls after complete mutation coverage is established.

Apply discipline: `verify-original-writer-patch.py --manifest <manifest.json> --source-dir <source-directory> --phase before` verifies every original target and refuses conflicting pre-existing helper files. `--phase after` verifies the full patched package. These commands are read-only; if any mismatch occurs, stop and regenerate/review against the deployed version. Back up exact targets and schema separately. Apply tables and helper files first with bridge APIs disabled, then original hooks as one maintenance release, verify hashes and exercise original form regressions. Keep bridge APIs disabled until live-writer inventory and concurrency acceptance are signed off. Rollback disables MAPA commands/dispatch first and reconciles every active reservation before removing hooks. Never drop reservation/ledger data or restore old operational databases to roll back code.

## Original manual form transaction adapter

`SourceManualTransactions.php` wraps the original archived action bodies without replacing their fields, SQL, permission branches or success/redirect behavior. The staged running, repair and analytics pages add a session CSRF token and one persistent request identity to each of their 18 POST forms. Supported database actions run in one transaction with `mapa_manual_commands` (created by `manual-command-ledger.sql`); same-request retries replay a generic outcome and changed payloads conflict. Private coordination policy requires a separate `form_hmac_secret` of at least 32 bytes. Request HMACs and generic receipts omit patient facts; never put this private secret in a page, snapshot or repository. Preserve the same request identity during a failed transport retry; a freshly reloaded form deliberately represents a new submission.

Covered actions: daily session start/close/reopen and off-road reversal; completed multi-patient trip save; existing manager trip edit/delete and odometer correction; repair place/odometer/item changes and completion; analytics administrator reopen. Original repair completion still uses its existing form and daily-road semantics, rather than the stricter new mobile repair command. Multi-patient insertion and closing odometer increment commit exactly once; a failure on the second patient or receipt rolls everything back. The legacy permission/category checks remain inside the original callback.

`SourceRepairPhotos.php` now covers repair initialization and append-photo actions in the same retry/transaction boundary. Existing form fields, redirect URLs and uploads/ambulance_repairs public path are retained. Photos must be actual JPEG/PNG/WebP, at most 10 files of 10 MB each (server body limits may be lower). A reviewed existing uploads parent directory is required; symlink targets and unexpected upload fields are rejected. File-content metadata is included inside the private request HMAC. The ledger exposes neither raw content digests nor uploaded names. Filenames are immutable request/content-derived HMACs with verified image extensions. Existing photos are never overwritten or deleted. Failed confirmed transactions remove only new files created by that request; ambiguous commits retain files so a committed DB reference cannot be broken. Files are flushed before database commit. Tests cover same multipart replay, changed-content conflicts, permission/CSRF denial, invalid image type, rollback, pre-commit interruption recovery and a lost response after commit.

A hard process death before database commit can leave an unreferenced immutable file. An identical retry verifies/reuses it and commits once; abandoned files require reviewed reconciliation against all database references and in-flight receipts under maintenance/ownership coordination. There is intentionally no automatic blind cleanup. File and SQL durability still depend on the host storage; this is recoverable coordination, not one atomic filesystem/SQL primitive.

Original historical passenger rows have no durable shared journey group ID; the adapter preserves existing per-row edit/delete distance semantics and does not invent grouping. Group-aware historical corrections require a separate explicit migration/review.

Local v8 verification: 59 source-workflow checks, 49 policy/archive checks, 30 exact original action-body checks, 16 multipart photo checks and 62 source-command checks (216 total). Tests execute the extracted staged action blocks against synthetic MySQL data, including rollback and role restrictions; they do not execute full original bootstrap/pages or replace browser/real-role acceptance.

## Explicit remaining blockers

1. `original_writers_coordinated=true` is only a commissioning flag, not proof. It remains false. Runtime schema/account attestation is implemented; runtime deployed-code hash attestation is not. The stage manifest deliberately states NOT_COMMISSIONED.
2. All mutation-bearing PHP files in the supplied archive now have staged guards, but the deployed site may differ and source writers may exist outside the archive (including cron, mobile endpoints, DB jobs and other modules). Compare deployed hashes and complete the live writer inventory before commissioning.
3. The staged database-only manual forms now have atomic receipts, but reviewed abandoned-photo reconciliation and historical multi-patient group identity remain unresolved. Original forms preserve their legacy validation and last-write behavior; transaction wrapping does not provide optimistic edit revisions or stronger business validation.
4. SourceCommands master edits now join the mutex/reservation guards. Other master writers outside this archive must do the same; source provider credentials and policy receipts must be commissioned without copying broad web-user privileges.
5. Current tests verify bridge and original manual action-body transaction/idempotency, helper guards and parallel reservation acquisition. The multipart fixture runs extracted exact original action code with synthetic session/permission stubs; it does not execute the whole website bootstrap or prove deployed ACLs. Full original PHP HTTP/form regressions, real permissions/CSRF, concurrent CAD-vs-MAPA dispatch, source schema parity and deployment recovery have not passed yet.
6. Original FLOAT odometer/distance columns are checked after every write against intended integer hundredths. Precision loss rejects and rolls back the command; a reviewed DECIMAL migration is needed for readings the legacy schema cannot represent. Original web writers do not yet have this precision safeguard.
7. New endpoints still need MAPA controllers/outbox/UI and capability gates. No crew button should be enabled solely because these files exist.

No real patient, fleet, account or provider data was written; no live endpoint, original website or service was changed.

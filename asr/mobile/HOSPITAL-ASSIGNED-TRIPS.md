# Receiving hospital early assignment contract

Local change; not deployed by this work. Existing `GET hospital/incoming` keeps `incoming` as real encrypted crew onboard reports. An additive `assigned_trips` array exposes current dispatched assignments before a matching crew report exists, only to the authenticated hospital bound to the current receiving place.

The response advertises `capabilities.hospital_assigned_trips: true` and `assigned_trips_truncated`. This projection polls up to 100 current destination candidates (101 queried to report truncation); it is not a guarantee of an exhaustive list when truncated. A fresh authenticated poll re-evaluates tenant, destination, assignment, active state and native driver/vehicle consistency. Tracking uses the same native projection as crew and caller. This is a read-only polling snapshot, not an atomic lock on dispatch.

Each early card has `order_id`, native `status`, `handover_state: awaiting_crew_report`, `can_acknowledge_handover: false`, `caller_reported`, `crew_observed: null`, destination, ambulance, authorized trip contacts, tracking and updated_at. It deliberately has no handover `id`, integer revision, condition or observed note. Do not send early cards to the handover acknowledgement endpoint or label them as patient onboard. `caller_reported` contains only reported problem, priority, consciousness, breathing, scene safety and patient count where present; its source is `caller_reported_dispatch_intake` and `observed_by_crew` is false. Missing intake stays null. These statements remain caller reports, not clinical assessments.

When a matching crew report is created, that order leaves `assigned_trips` and appears in existing `incoming`. Destination/crew changes never forward the old clinical report. The new hospital can see the current assignment and caller intake, while an explicitly reviewed crew report transfer remains required. Completion, withdrawal, deleted/foreign resources, mismatched native crew/vehicle or destination changes remove prior hospital access on the next poll.

Old APKs continue using `incoming` unchanged. Updated Android screens must handle this separate array, show “Assigned — awaiting crew report”, display caller facts separately, and hide readiness/acknowledgement actions until a real handover arrives. No pre-onboard Firebase notification is added by this change; notification eligibility and provider setup remain separate.

MAPA optional Firebase-enabled Android build

The ordinary ../build.ps1 path includes no Firebase SDK and says so in the
app. This Gradle build adds NativeMessagingService and NativeFcmClient to the
same package ID and core application. Do not publish an unverified FCM build.

Prerequisites:
- JDK 17 or later (JDK21 is present in the retained Android toolchain).
- Gradle 8.11.1, Android Gradle Plugin8.9.2, Android35 SDK/build tools.
- Firebase Android config for in.asr.ambulance from the operator's project.
- The EXISTING MAPA signing key/certificate. Never generate a different key
  for an update; Android will reject it or require deleting installed data.

PowerShell environment, using your actual paths:
$env:MAPA_GOOGLE_SERVICES_FILE = '<private path to google-services.json>'
$env:ANDROID_HOME = '<Android SDK root>'
$env:JAVA_HOME = '<JDK root>'
gradle -p mapa-android/fcm --no-daemon assembleRelease

The Gradle project intentionally produces an UNSIGNED release APK. Sign with
the existing MAPA release key using the reviewed apksigner procedure and check
certificate SHA256 against the previous installed APK. Never distribute the
unsigned output. Version code/name are read from ../AndroidManifest.xml;
increase them before a public update when required.

The build reads only the selected Android app's Firebase public identifiers
from the supplied JSON into generated resources. It rejects service-account
JSON; server credentials must remain on the backend. No Analytics dependency
is included. FCM auto-init starts disabled until authenticated crew or hospital login and
notification permission, and registration is bound to that exact session.

Pinned messaging SDK: com.google.firebase:firebase-messaging:24.1.2. This
build uses its supported getToken/onNewToken API. Newer Firebase releases
introduce installation-ID registration; migrate both server target and phone
together rather than changing only one end.

Configuration, provider commissioning and phone acceptance are documented in
fleetbase/asr/mobile/PUSH-SETUP.txt. A successful compile or server mock test
does not prove notification receipt on a physical phone.

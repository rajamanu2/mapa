Android installation, daily use and operator checks

Supervised pilot · 30 September 2026 rollout guide

Before you begin

Use an Android phone with mobile data or Wi-Fi and location enabled. MAPA supports Android 8 or newer. A USB cable and Developer options are not required for ordinary crew use.

Each crew member needs an individual MAPA account already linked by the administrator to the correct driver and ambulance in ASR Health. Installing the app does not create an account or assignment. Use a separate login for each crew member.

Selected call workflow: control answers its existing telephone number and enters the details in MAPA New Call. No Exotel number activation, speech service or telephone API is required.

This is a supervised pilot. Earlier GPS and web ambulance-location verification used version 1.10 on the connected Android 16 phone. Version 1.11 still needs a complete handset check, including assignment alerts, acceptance, trip stages, screen lock and connection recovery. Each phone needs its own acceptance result.

1 · Install the tested app

Download MAPA Crew 1.11.0

  1. Open this guide on the phone and download the APK from the MAPA link above.
  2. Open the downloaded file. If Android asks, allow this browser or file manager to install this APK, then complete installation. Turn that installer permission off afterward if it is no longer needed.
  3. If MAPA is already installed, choose the compatible update. Do not uninstall or clear app data to solve an update error. Ask the administrator to check the signing identity and version.
  4. Open MAPA. This update is 1.11.0-pilot, version code 14, signed with the same certificate as the previously installed 1.10 app.

Installer SHA256: 7247e4cc0fc9d2a2e2543358c316d43645de46e733587f85445b35401aef6cf6. This newly built update passed software and signing checks. It has not yet been installed and verified on all crew phones.

2 · Sign in to ASR Health

  1. Set the server to https://mapa-asr-health.pages.dev. Do not add /fleet-ops or /call-intake/, and do not use localhost.
  2. Enter your own crew email and the password provided privately by the administrator. Passwords are not included in this guide.
  3. Check the crew name and ambulance registration. If either is wrong, stop and ask control to correct the assignment before sharing location.
  4. Use the language option to select English or Telugu. English is the default.

Control must register your actual crew identity and ambulance before issuing your login. Old training identities are not real fleet registrations.

3 · Start location sharing

  1. On Home, tap Start duty or Resume location sharing.
  2. Read the location notice and tap Start sharing. Signing in alone does not start GPS.
  3. Allow location while using the app, enable Precise location, and allow MAPA notifications. Keep the app open while sharing starts.
  4. Wait for GPS is being shared and a recent Last received time. Keep location and Internet on. A MAPA location-sharing notification should remain visible.
  5. If accuracy is poor, test in an open safe place and let the phone obtain a better fix. A 100-metre reading is approximate and must not be treated as an exact entrance or pickup point.

Daily check: crew identity → ambulance registration → Start sharing → recent Last received → control confirms the same ambulance on the web.

Open Travel record to see accepted reports, timestamps and accuracy. Reopen MAPA after a reboot, update or force-stop and explicitly resume sharing. Do not assume Android has restarted it.

4 · Find the ambulance on the web

Operations map

Open MAPA Operations. In the live operations sidebar, select Ambulances, then choose the linked ambulance to centre the map and open its details.

Check its registration, crew and Last seen. An Online label alone is not proof of a fresh GPS report or availability for a new call.

Received location history

Open Call Intake → Crew locations → select the crew → Load location records.

Compare device time, server receipt time and accuracy. Load the records again for the latest evidence. The table shows recent reports; it does not prove a completed journey.

Phone updates are normally sent on an approximately ten-second cycle, subject to GPS availability, connection and Android scheduling. The history view shows up to 200 accepted reports within 24 hours. Do not interpret a stored map pin as continuous live tracking.

5 · Calls and end of shift

  1. Keep MAPA open or its explicitly started duty/location service running. The app checks for assignments on an approximately ten-second cycle; notifications need Android permission. Control records and reviews the pickup, destination and caller coordination details, then assigns an eligible crew and ambulance.
  2. On the phone, read the assigned call and confirm the current pickup and callback details. Acknowledge only after reviewing the actual assignment from control. Do not create a fictional incident to test this step.
  3. Control checks that the acknowledgement reached the web. If a call changes, refresh and review it again.
  4. For a supported ASR call, accept it and wait for a new Last received time after acceptance. Confirm Response started, then Transport in progress when those events occur. Tap Hospital handover complete only after the receiving team has accepted handover, then confirm the separate prompt. Wait for MAPA to confirm the update. At the end of duty, tap End duty. MAPA may block ending duty while an active dispatch remains.

This update supports crew-confirmed completion for the configured single-destination ASR workflow. Custom, multi-stop, return, proof/photo, manifest and financial workflows need control’s console. Crew confirmation does not replace independent hospital acceptance or clinical records. Polling alerts require an active app or duty service; Firebase is optional and requires a separate configured build and delivery test. Reopen MAPA and resume sharing after reboot or force-stop. Use control-room telephone coordination when an alert or update fails.

Control · Enter and dispatch a manual call

  1. Answer ASR Health’s existing telephone number outside MAPA. Open Call Intake and select New Call.
  2. Enter the caller-reported problem, callback number when available, pickup address and landmark/access directions. Indian ten-digit mobile numbers are normalized to +91; international numbers need a leading +. If the number is unknown, leave it blank and establish another coordination method.
  3. Search for the village or landmark and select a candidate, or drop the pin on the embedded map. Check the filled coordinates and address, read the location back to the caller and confirm the exact pickup point. A search result alone is not a verified pickup.
  4. Save the intake, review the priority and required ambulance capability, choose the actual receiving destination and confirm the pickup coordinates. Saving a draft does not dispatch an ambulance.
  5. Select an eligible crew/ambulance and explicitly confirm dispatch. If none is eligible, inspect the reason: duty, active assignment, binding, capability or stale GPS. Resolve the cause and refresh eligibility.
  6. Verify that the crew receives and accepts the same call, then monitor fresh location reports and the recorded trip stages. An alert is not acceptance, and an old pin is not a fresh location.

Before the fleet rollout, complete this entire workflow in a supervised, clearly identified exercise without fabricating a real incident. The current shared backend still depends on this PC, Docker and Internet; permanent hosting must be commissioned for PC-off operation.

When reporting a problem, send the exact message, time, app version and ambulance registration to your administrator. Do not include a password or patient information.

Administrator checklist for each new user

  • Create/verify an individual active native ASR Health user with the intended role. Crew do not need platform administrator privileges.
  • Link that user to the correct Driver record and its assigned Vehicle. Check the registration with the crew.
  • Have the MAPA administrator enable the matching company-bound mobile crew binding. Web account creation alone is not enough; there is no public crew self-signup.
  • Provide the user’s credentials privately. Do not share a login across multiple phones: they would report positions for the same ambulance.
  • Verify login, foreground GPS, matching map/history timestamps, a safe short movement test, at least two minutes of locked-screen reporting, Internet loss/recovery on each device. Check acknowledgement and crew-confirmed trip stages when an actual assigned call arrives; do not generate an incident for testing. Before claiming remote push readiness, configure Firebase and verify a notification with the phone locked.
  • Record results before approving that phone for the pilot. If any required test fails, mark that device pending and keep control-room coordination in place.
  • Confirm this PC and Docker remain running throughout the pilot. Permanent hosting and a controlled release-signing/update process are still rollout work.

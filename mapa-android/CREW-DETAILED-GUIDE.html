MAPA · ASR HEALTH

Crew registration, calls and trip-end reports

For the new registration-enabled Android release. A driver submits their own details once, and command-center staff verify the ambulance and approve the phone connection.

Download MAPA Crew 1.12

1. Register on the crew phone

  1. Install or update MAPA on Android 8 or later. Keep the existing installed app when updating so its private connection is preserved.
  2. Open MAPA. Check that the server address is https://mapa-asr-health.pages.dev.
  3. Select Register / connect to ASR Health (the new crew registration button). Enter the driver's real name, personal contact email, phone number, ambulance registration and name, and hospital or base name.
  4. Read the collection notice and consent to send these details. Enable location, allow precise location, and take a fresh registration selfie using the camera.
  5. Submit once. Keep the app installed while the screen shows Pending command-center approval. Check status after staff approve. Do not repeatedly register the same driver.

No numbered User1 password is needed for a new crew registration. Existing assigned accounts can continue through the existing sign-in option. The contact email is recorded as a submitted contact, and registration does not create an email mailbox.

2. Command center approves the driver

  1. Sign in at MAPA operator desk using an approved administrator account.
  2. Open Crew registration and refresh. Select the pending driver and view the private registration selfie.
  3. Verify the driver in person or through the organization's approved identity process. Match the actual ambulance registration and hospital/base to their native MAPA records.
  4. Select the verified ambulance and hospital/base, check the identity confirmation, then select Approve crew connection.
  5. If the details do not match, enter a reason and reject. An existing ambulance assignment cannot be claimed by a form submission. Create any genuinely missing ambulance or hospital record through the normal authorized console workflow.

Approval records the native crew account and linkage in ASR Health. It does not start duty, share ongoing GPS or dispatch a call.

3. Start duty and verify location

  1. On the phone, check the registration status and connect after approval. Confirm the displayed crew name and ambulance registration.
  2. Choose Start duty / Resume location sharing, then Start sharing. Allow precise location and notifications. Keep phone Location switched on.
  3. Open phone setup and use Test alert sound to check the local alert sound. This test lasts at most 30 seconds and has a stop button; it creates no ambulance call. Verify that you hear it on this handset.
  4. Verify a recent server receipt on the phone. In command center open Crew locations and check that the correct ambulance has a recent fix, receipt time and realistic accuracy.
  5. Keep the app's duty/location service running, network available and the relevant notification channel enabled. After reboot, force-stop or a stopped service, reopen MAPA and explicitly resume sharing.

The phone retains an encrypted, revocable connection for a bounded period. Command center can revoke a lost phone. Signing out removes the connection and requires another approved registration or an existing authorized login; this is not a permanent unauthenticated login.

4. Receive and accept a call

  1. The operator answers the existing telephone number, enters NEW CALL, confirms the caller's pickup pin, reviews the destination and explicitly dispatches an eligible crew.
  2. While the app or duty service is active, new assigned work triggers an alert. Open/check the assigned call to stop the repeating alert.
  3. Read the pickup, callback number and destination, then explicitly accept/acknowledge the call. Checking the alert alone does not accept the call.
  4. Wait for a fresh received GPS report after acceptance. Confirm response start and transport only when those events occur.

Android notification permission, channel settings, silent mode, Do Not Disturb, network, battery controls and service availability can prevent audible alerts. Firebase remote push remains unconfigured. Test ringing on each handset, including a locked screen, and keep telephone coordination available if an alert or acknowledgement is missing.

5. Save the trip-end evidence, then end duty

  1. At the actual receiving/handover point, confirm handover with the receiving team. Enter the trip-end note.
  2. Take a fresh trip-end photograph of the ambulance or safe handover area. Avoid patient faces, documents or unnecessary clinical details.
  3. Keep precise GPS and network available. MAPA includes the fresh non-mock device coordinates, fix time and accuracy and checks them against the same phone session and assigned trip.
  4. Submit the trip completion and wait for the server receipt. If the response is uncertain, retry the exact saved update. Do not create another completion or end duty while the receipt is uncertain.
  5. If an unsubmitted capture is too old when connectivity returns, follow the explicit review/recapture message. Keep the note, capture fresh evidence and submit a new update only after the old update has been definitely rejected.
  6. Once completion is confirmed and no active assignment remains, explicitly select End duty / Stop sharing. Verify the duty-off receipt. Ending a trip and ending the shift are separate actions.

Command center opens Trip reports to see the received note, private photograph, coordinates, accuracy, capture/fix time and receipt time. Device GPS and a crew photograph are records for review; they do not independently prove patient handover.

Language

The new registration, consent, trip-photo and local sound-test screens are currently in English. The existing Telugu option covers established screens; these new forms have not completed Telugu localization or handset acceptance.

Information collection and access

MAPA sends the registration details and selfie to ASR Health for staff review and stores the approved driver/ambulance/base relationship. During explicit duty sharing it records device location observations. Completion stores the crew note, photograph and associated location evidence. Photographs are served only through authenticated access; they are not public download files. A selfie is an identity photograph for review, not an automated biometric identity check. Contact ASR Health command center about corrections, a lost phone or access revocation.

Before all 25 phones start using it

Verify registration, approval, correct vehicle linkage, fresh GPS, locked-screen alerts, call acknowledgement, trip completion and duty-off on three phones first, then ten, then twenty-five. Check camera denial/cancellation, network recovery and session expiry. Passing software tests is not a physical-phone acceptance test.

The current share link depends on the Windows PC, Docker and internet staying available. A Windows/Android installation does not make the backend always-on. Complete the commissioned server migration before depending on access when this PC is off.
